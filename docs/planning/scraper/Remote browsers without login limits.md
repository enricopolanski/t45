# Test three cloud browsers, then drop Bright Data

**Five cloud browsers have no password gate and meet T45's other requirements on paper: Browserless, Browser Use Cloud and Browserbase, to be tested in that order, with Kernel and Anchor in reserve.** None of the five documents a KYC or compliance step before logins. All five accept Playwright `connectOverCDP`, give German exit IPs from residential or ISP pools and keep logged-in state in server-side profiles. The scraping networks closest to Bright Data (Oxylabs, Scrapeless and Zyte) have the same "no data behind a login" or verification rules, so they are ruled out. No independent source shows any option getting through amazon.de, so the order reflects fit with T45's runner, not proven results. **Amazon's terms are the bigger issue, and switching vendors does not change them.** The amazon.de AGB (last changed 01.10.2026) exclude collecting prices and using robots from the user licence. Their AGENTEN section requires `Agent/<name>` in every request's User-Agent and forbids hiding agent use by imitating human input or by filling in or circumventing CAPTCHAs. All five vendors solve CAPTCHAs automatically, and so does today's Bright Data setup. Cost does not decide anything: a baseline run moves about 60 MB, which is under $1 with any vendor.

_All sources were read on 12 November 2026. † marks a claim seen only in a search snippet or a fetch-tool summary, not verbatim. Benchmarks published by a company that sells one of the products are labelled vendor-run. Nothing here is legal advice._

## Start with Browserless, then Browser Use, then Browserbase

The order is set by how far each option is from T45's current wiring, and the wiring is narrow. The server's `WEB_BROWSER_URL` carries the credential as URL user and password. The runner strips it and gives the VM's Playwright CLI the bare endpoint plus an `Authorization: Basic <placeholder>` header. On the way out, it substitutes the real `base64(user:password)` into that header, for one allowed host only ([SandboxManager.ts](../../../apps/runner/src/SandboxManager.ts)). That design suits a vendor whose WebSocket takes a static secret in a header with no session-creation step, so Browserless comes first. Browser Use comes next: its direct-connect key sits in the query string, which microsandbox can also substitute. Browserbase, Kernel and Anchor need the runner to create each session over REST first, because the German proxy and the saved profile are session-creation options. The requirements allow that step, but it is real code.

Four things decide the choice, in this order. **Login policy comes first.** It removes the scraping networks and makes Steel and Airtop risky on amazon.de (next table). **Wiring comes second.** A static secret in a header or query string on a fixed host is a configuration change for T45. A per-session URL on a changing host needs a broker on the runner and a wider egress rule. **Session length comes third.** T45's baseline step run lasted 21 minutes and the chat 13 ([PR 10 report](../pr10.report.md)). That rules out every 15-minute plan and leaves Browserless only an hour of headroom even on Scale. **Persistence mechanics come last**, and they are where an easy connection hides work. On Browserless and Browser Use, the profile is saved by a call that Playwright CLI does not make: a CDP command for one, a REST stop for the other. Even the "just change the URL" options need something on the host to keep logins.

## Each shortlisted option, with its catch

### Browserless needs the least change but has the shortest sessions

Browserless is the only shortlisted vendor whose cloud docs send the token as a header on the WebSocket upgrade. Its DevTools guide recommends `Authorization: Bearer` because this "keeps the token out of the endpoint URL", and was tested against `wss://production-sfo.browserless.io` ([Browserless DevTools MCP](https://docs.browserless.io/ai-integrations/chrome-devtools-mcp)). The open-source server reads `?token=` first. Otherwise it accepts the header as either `Bearer <token>` or `Basic <base64(token:)>` ([browserless utils.ts](https://github.com/browserless/browserless/blob/main/src/utils.ts)). **If the cloud behaves the same, T45 only has to set `WEB_BROWSER_URL=wss://<token>:@production-ams.browserless.io/stealth?…`, with no code change.** The Amsterdam host name itself was read only through a page summary†. That is unverified and is the first live test. No REST step is needed, because everything goes in the URL. The German proxy is `proxy=residential&proxyCountry=de&proxyLocaleMatch=1`, and stealth routes keep the exit IP "sticky by default" ([Browserless proxies](https://docs.browserless.io/baas/bot-detection/proxies)). Then come `solveCaptchas=true` and a `timeout` ([Browserless Playwright MCP](https://docs.browserless.io/ai-integrations/claude-code-playwright-mcp)), and `profile=<name>` for a saved login ([Authenticated Profiles](https://docs.browserless.io/baas/features/authenticated-profiles)). Its CAPTCHA command lists `amazonWaf` among the accepted types ([CDP extensions](https://docs.browserless.io/api-reference/cdp-extensions)). No other shortlisted vendor names Amazon's challenge. That is a capability claim, not a success rate. One forum user found Browserless "hit-or-miss against Amazon's detection" on an Amazon logistics page ([n8n community](https://community.n8n.io/t/browserless-http-request-node-loading-indefinitely-when-scraping-swiship-amazon-tracking/295812)).

The catches are session length and saving logins. **The longest session is 15 minutes on Prototyping, 30 on Starter and 60 on Scale**† ([Browserless pricing](https://www.browserless.io/pricing)). The 21-minute baseline run therefore needs Starter ($140/mo) or above, and an agent run longer than an hour gets cut. Browserless also "provisions a browser per connection" ([Browserless DevTools MCP](https://docs.browserless.io/ai-integrations/chrome-devtools-mcp)), so a reconnect lands in a fresh browser. A profile holds cookies (including HttpOnly), localStorage and IndexedDB. Changes made during a session "won't affect the original profile", and a profile is saved only by the `Browserless.saveProfile` CDP command or the dashboard's "Sign in via remote browser" flow ([Authenticated Profiles](https://docs.browserless.io/baas/features/authenticated-profiles)). Playwright CLI sends neither. In practice, a person logs in once through the dashboard or a host-side step, and agents reuse a read-only snapshot until the site expires it. Profile retention and encryption are undocumented. Browsers run in Amsterdam, but customer data is "primarily stored in the United States", and a DPA comes only with Enterprise† ([Browserless trust](https://www.browserless.io/trust)). Two ToS clauses matter. Section 11(k) prohibits using the service "to interfere with or circumvent the security features of the Service or any related website, other websites, or the Internet". Section 2 bars exploiting the service "without express written permission" ([Browserless ToS](https://www.browserless.io/terms-of-service)). The first bears on amazon.de and the second on T45 serving many tenants.

### Browser Use scores highest, but only on its own benchmark

Browser Use Cloud leads Stealth Bench V2 with **90.5%**. The others score Anchor 82%, Kernel 80.5%, Browserbase 78.5%, Browserless 77.5%, Steel 74.5% and Hyperbrowser 73.5%, against 3% for plain headless Chrome. **Browser Use ran the benchmark itself**, on 100 sites that "were picked because Browser Use Cloud historically got through where stock Chrome with a US proxy did not", and tested several competitors on standard rather than top tiers ([Browser Use, cloud browsers compared](https://browser-use.com/cloud-browsers)). One Browser Use page cites an "independent rerun" (Browser Use 90%, best other 85%) without naming who ran it ([Browser Use benchmark](https://browser-use.com/benchmarks/browsers)), and no such rerun was found. Its March V1 run on 71 sites put the same three on top: Browser Use 81%, Anchor 77%, Kernel 67%, Steel 47%, Browserbase 42% and Hyperbrowser 40% ([Browser Use blog](https://browser-use.com/posts/stealth-benchmark)). The clearest signal in both runs is that any managed stealth browser beats stock Chrome by a wide margin. The gaps between vendors sit inside a site set the vendor chose.

The wiring is light. A direct URL, `wss://connect.browser-use.com?apiKey=<key>&proxyCountryCode=de`, takes `profileId` and `timeout` (up to 240 min) as further query parameters. **It is documented only on a tutorial page** ([Browser Use OpenClaw](https://docs.browser-use.com/cloud/tutorials/integrations/openclaw)). T45 would substitute the key in the query. The documented route is REST: `POST /api/v4/browsers` with the `X-Browser-Use-API-Key` header returns a `cdpUrl`, which the docs connect to without headers ([Browser Use Playwright](https://docs.browser-use.com/cloud/browser/playwright-puppeteer-selenium)). That makes it a per-session capability the VM would hold. Either way, "`browser.close()` and disconnecting CDP do not stop the managed browser". Stopping takes `PATCH /browsers/{id}`, and profile state is "saved to the profile when it stops" ([Browser Use profiles](https://docs.browser-use.com/cloud/guides/authentication)). The host therefore owns the session's end. Whether a direct-connect session saves or stops on disconnect is undocumented. Every session runs a hardened Chromium fork whose fingerprints are "randomized per session to appear as a real user" ([Browser Use stealth](https://docs.browser-use.com/cloud/browser/stealth)). CAPTCHA solving is on by default. The proxy docs even use "Get the iPhone 16 price on amazon.de" as their example ([Browser Use proxies](https://docs.browser-use.com/cloud/browser/proxies)), but an example is not evidence. Logins are a showcased use, with a 1Password task reading "Open amazon.com, log in, and check my recent orders" ([Browser Use 1Password](https://docs.browser-use.com/cloud/guides/1password)).

Three cautions apply. **The Frankfurt deployment disables automatic CAPTCHA solving and custom proxies** ([Browser Use EU](https://docs.browser-use.com/cloud/eu-deployment)), so amazon.de work would run on the US control plane with a German exit IP. SOC 2 Type II and a DPA with EU SCCs still apply there ([Browser Use security](https://browser-use.com/security)). **The ToS (revised 15 Oct 2026) bars using the service to "engage in or use any data mining, robots, scraping, or similar data gathering or extraction methods"** and to circumvent "geographic restrictions … including through the use of virtual private networks" ([Browser Use ToS](https://browser-use.com/legal/terms-of-service)). Read literally, that covers the product's own purpose, so T45 needs written confirmation of what it means. Finally, Browser Arena recorded 72 of 100 Browser Use runs failing on 12 Nov 2026 ([Browser Arena](https://www.browserarena.ai/)). Notte, a competitor, runs that benchmark, and the failures could sit on the harness side. Even so, it is a reason to test reliability directly. Concurrency starts at 10 sessions and rises to 1,000 with lifetime spend ([Browser Use concurrency](https://docs.browser-use.com/cloud/guides/concurrency)). The price is $0.02 per browser-hour plus $5/GB ([Browser Use pricing](https://browser-use.com/pricing)).

### Browserbase keeps logins longest but needs a session broker

Browserbase is the most mature home for long-lived logins. A context persists the Chromium user-data directory: cookies, localStorage, IndexedDB and autofill. Contexts "live indefinitely" and are "uniquely encrypted at rest" ([Browserbase contexts](https://docs.browserbase.com/platform/browser/core-features/contexts)). Browsers can run in `eu-central-1` (Frankfurt) ([Browserbase regions](https://docs.browserbase.com/optimizations/latency/multi-region)), and each runs in its own VM that is "killed and recreated" after the session ([Browserbase security](https://docs.browserbase.com/account/enterprise/security)). Paid plans allow 6-hour sessions and 25 to 250+ concurrent browsers, but the DPA comes only with Scale ([Browserbase plans](https://docs.browserbase.com/account/billing/plans)). The docs walk through a login strategy: sign in through Live View or code, then persist the state to a context ([Browserbase authentication](https://docs.browserbase.com/platform/identity/authentication)). The Terms of Use say nothing about logging into third-party sites ([Browserbase ToS](https://www.browserbase.com/terms-of-service)). Browserbase did well in the third-party data that exists. In the Halluminate benchmark it had 3.4% stealth failures, third best; that benchmark discloses no vendor ties, though its independence is not established, and it dates from 22 Nov 2025 with no Amazon sites ([Halluminate](https://www.halluminate.ai/blog/browserbench)). It also succeeded on 100 of 100 runs in Browser Arena, a lifecycle benchmark operated by competitor Notte ([Browser Arena](https://www.browserarena.ai/)).

The price of that maturity is a broker. The German proxy and the context are session-creation options. The runner therefore has to call `POST /v1/sessions` with the `X-BB-API-Key` header ([Browserbase create session](https://docs.browserbase.com/reference/api/create-a-session.md)), set `keepAlive` so the session survives a disconnect, and hand the VM `wss://connect.browserbase.com?apiKey=<placeholder>&sessionId=<id>` for query substitution ([Browserbase Braintrust guide](https://docs.browserbase.com/integrations/braintrust/typescript)). The docs do not say what the returned `connectUrl` contains, so it should not reach the VM until checked. **The stronger "Verified" browser, whose fingerprints "bot protection partners recognize", needs the Scale plan and an eligibility check with sales** ([Browserbase agent identity](https://docs.browserbase.com/platform/identity/overview)). Developer and Startup get "Basic" stealth, and the CAPTCHA types solved are not listed. The managed residential proxies come from third parties that refuse banking, government, webmail and ticketing sites ([Browserbase proxies](https://docs.browserbase.com/platform/identity/proxies)). Amazon is not named, but a login to Outlook or a bank would need T45's own proxy.

### Kernel has the friendliest login policy but may not reach Amazon

Kernel is the only vendor whose policy text answers T45's question directly. Its AUP says "If a person may lawfully browse a site and take an action on it, their agent may too". It bans unauthorised account access but "does not prohibit using credentials you own, or that a user has authorized you to use on their behalf" ([Kernel AUP](https://www.kernel.sh/docs/acceptable-use)). The technical fit is just as good. Kernel offers a **German ISP proxy whose exit IP "persists across sessions"**, plus residential and mobile proxies, none of them billed by bandwidth ([Kernel proxies](https://www.kernel.sh/docs/proxies/overview)). Profiles hold the whole user-data directory, "encrypted end to end using a per-organization key" ([Kernel profiles](https://www.kernel.sh/docs/browsers/profiles)). Stealth and the CAPTCHA solver are on every plan. The solver covers reCAPTCHA, hCaptcha, Cloudflare/Turnstile and press-and-hold, and does not list AWS WAF ([Kernel stealth](https://www.kernel.sh/docs/browsers/bot-detection/stealth)). An idle browser can be kept for up to 72 hours ([Kernel termination](https://www.kernel.sh/docs/browsers/termination)), though a CDP socket "typically" lasts up to an hour before a reconnect is needed ([Kernel FAQ](https://www.kernel.sh/docs/browsers/faq)), and a DPA applies automatically to EU personal data ([Kernel ToS](https://www.kernel.sh/docs/tos)).

Two clauses in the same AUP could stop it on amazon.de. First, **its upstream proxy providers refuse "Select e-commerce platforms", "evaluated by the provider case by case"**. Amazon is not named either way. The workaround is to bring your own proxy, which starts on the $200/mo Start-Up plan. Second, Kernel "may require … reasonable identity or business verification before granting or continuing access to … higher concurrency, or proxy capacity" ([Kernel AUP](https://www.kernel.sh/docs/acceptable-use)). That is not a login gate, but it could become a verification step. The wiring differs from the rest. The browser is created over REST with a Bearer key, and its `cdp_ws_url` carries a per-session `jwt` on a per-session host at port 8443 ([Kernel OpenAPI](https://api.onkernel.com/spec.json)). Kernel warns that "hostname can change between sessions" ([Kernel network access](https://www.kernel.sh/docs/info/network-access)). T45 would let the VM hold that session token, which Kernel says to "treat … as credentials" ([Kernel MPP](https://www.kernel.sh/docs/info/mpp)), and widen egress to `*.onkernel.com:8443`. The VM never sees the account key, but anyone holding the URL controls that logged-in browser until it ends. The EU region (`eu-west`) also needs Start-Up ([Kernel regions](https://www.kernel.sh/docs/browsers/regions)). The security page claims GDPR certification and, further down the same page, lists GDPR as "In Progress" ([Kernel security](https://www.kernel.sh/docs/security)).

### Anchor tops the third-party stealth test, at $2,000 a month

Anchor has the best stealth numbers that do not come from a vendor's own benchmark: **1.7% stealth failures in Halluminate's benchmark**, the lowest there ([Halluminate](https://www.halluminate.ai/blog/browserbench)). It is also second in Browser Use's run at 82%. Its identities store credentials and rerun the login flow when a saved profile expires ([Anchor identities](https://docs.anchorbrowser.io/essentials/authenticated-applications)). That is the most hands-off answer to logins that expire. The strongest configuration costs the most, though. Per the docs, "Extra Stealth" and the Frankfurt region sit on the Growth plan at $2,000/mo (the homepage puts EU regions under Enterprise), and the default infrastructure runs in AWS `us-east-2` ([Anchor pricing](https://docs.anchorbrowser.io/pricing); [Anchor security](https://docs.anchorbrowser.io/security)). The wiring is REST with the `anchor-api-key` header†, then `wss://connect.anchorbrowser.io?apiKey=<key>&sessionId=<id>` ([Anchor quick start](https://docs.anchorbrowser.io/quickstart/use-via-code)), which suits query substitution. The docs disagree, however, on whether the returned `cdp_url` "carries the API key in the query string" ([Anchor sandboxes](https://docs.anchorbrowser.io/integrations/sandboxes)), so the broker should never forward it. Recording is on by default ([Anchor sessions](https://docs.anchorbrowser.io/quickstart/browser-sessions)), so logins would be recorded unless it is turned off. The SaaS terms bar making the service available to third parties "as part of a time-sharing, outsourcing or service bureau environment" ([Anchor terms](https://anchorbrowser.io/saas-terms-05-25-2025)). T45 should get that cleared for multi-tenant use before relying on Anchor.

### Self-hosting Chrome gives the most control but has the least evidence

The do-it-yourself route works without a vendor's login rules, but nothing shows it works on amazon.de, and every piece is T45's to run. Several residential proxy providers restrict by target domain, not by login: Decodo, IPRoyal, Oxylabs and Webshare. None of the lists read names Amazon, though only IPRoyal's was read in full ([IPRoyal domain terms](https://docs.iproyal.com/proxies/residential/domain-access-terms); [Webshare restricted activities](https://help.webshare.io/en/articles/9987853-restricted-activities-with-webshare-proxies)). German exit targeting was not confirmed from a full page for any of them. SOAX makes identity verification "a condition of access to the paid Platform" ([SOAX KYC](https://soax.com/legal/kyc)). NetNut's network was disrupted by Google and the FBI in July 2026 ([The Hacker News](https://thehackernews.com/2026/07/google-disrupts-netnut-residential.html)), so it is out. The stealth tooling does not fit T45's split either. rebrowser-patches says it patches "the library code only, not the browser" ([rebrowser-patches](https://github.com/rebrowser/rebrowser-patches)). The fixes would therefore have to go into the Playwright that Playwright CLI uses inside the VM, kept in lockstep with Playwright releases. Camoufox is Firefox driven over Juggler, so it cannot be a CDP target, and it warns it "may not be suitable for stable production use" ([Camoufox](https://github.com/daijro/camoufox)). CDP has no authentication of its own†, and Chrome's `--proxy-server` cannot carry proxy credentials†. T45 would need an authenticated tunnel per agent plus a forwarder or IP allowlist for the proxy. Solving CAPTCHAs means a service such as 2Captcha or CapSolver, both of which offer AWS WAF token tasks ([2Captcha](https://2captcha.com/api-docs/amazon-aws-waf-captcha); [CapSolver](https://docs.capsolver.com/en/guide/captcha/awsWaf/)). It is the only route where T45 alone decides the User-Agent and whether to use stealth at all. T45's own runner Chromium, however, got Amazon's 503 robot page after a few searches ([PR 10 report](../pr10.report.md)). For "I just want it to work", this is the last resort.

## Amazon's terms forbid the CAPTCHA solving every option ships

The amazon.de AGB page, loaded in a real browser on 12 November 2026, shows "Zuletzt geändert: 01.10.2026" ([amazon.de AGB](https://www.amazon.de/gp/help/customer/display.html?nodeId=201909000)). The **LIZENZ UND ZUGANG** clause grants a limited, non-commercial licence. That licence does not include "eine Erfassung und Nutzung von Produktinformationen, Beschreibungen oder Preisen" or "die Nutzung von Data-Mining, Robotern oder ähnlichen Datenerfassungs- und Extraktions-Programmen". The **AGENTEN** section applies whenever someone uses, allows, activates or causes the use of an agent. It requires every HTTP request to declare "Agent/ [Agentenname]" in its User-Agent. It forbids hiding agent use, whether by "(a) Nachahmung der Geschwindigkeit oder des Musters menschlicher Tastenanschläge, der Seitennavigation oder anderer Interaktionen" or by "(b) Ausfüllen oder Umgehen von CAPTCHAs oder anderen Maßnahmen, die dazu dienen, Computer von Menschen zu unterscheiden". It also forbids circumventing measures that block or restrict agents, and lets Amazon restrict agents at its discretion, including by technical means ([amazon.de AGB](https://www.amazon.de/gp/help/customer/display.html?nodeId=201909000)). **This applies to every option in this report, and equally to the Bright Data setup that produced T45's baseline.**

Part of what the clause names is what the products sell. All five shortlisted vendors solve CAPTCHAs automatically, and Browserless names Amazon's own `amazonWaf` ([CDP extensions](https://docs.browserless.io/api-reference/cdp-extensions)). Browser Use randomizes fingerprints "to appear as a real user" ([Browser Use stealth](https://docs.browser-use.com/cloud/browser/stealth)). None of the sources read says which User-Agent any vendor sends, or whether any imitates human typing or navigation. The benchmarks above score exactly how well a browser avoids being recognised as automated. T45's current runner note already tells agents "The browser deals with CAPTCHAs itself" ([SandboxManager.ts](../../../apps/runner/src/SandboxManager.ts)). Amazon's robots.txt adds `Disallow: /` for agent user agents including Claude-User, ChatGPT-User and Perplexity-User ([amazon.de robots.txt](https://www.amazon.de/robots.txt)). Logging in raises the stakes. The account belongs to the T45 user, the AGB make that user responsible for keeping the password confidential, and the AGENTEN section reaches whoever allows or activates the agent ([amazon.de AGB](https://www.amazon.de/gp/help/customer/display.html?nodeId=201909000)). Vendor terms can pass the problem on. Steel, Airtop, Zyte and Oxylabs forbid use that violates a target site's terms, Browserless forbids circumventing other websites' security features, and Kernel makes the customer "responsible for your relationship with the sites you visit, including their terms of use" ([Kernel AUP](https://www.kernel.sh/docs/acceptable-use)).

For context, and without drawing conclusions: in 2014 the German Federal Court of Justice (BGH) held that merely ignoring click-accepted AGB does not make screen scraping unfair competition, and added that "Das Überwinden technischer Schutzvorrichtungen könnte zwar unlauter sein" ([LTO on BGH I ZR 224/12](https://www.lto.de/recht/hintergruende/h/bgh-urteil-izr22412-screen-scraping-flugdaten-automatisiert-auslesen-ryanair-reiseportal)). In the US, Amazon won a preliminary injunction against Perplexity's Comet agent in March 2026, accusing it of accessing password-protected customer accounts. The Ninth Circuit vacated it in August on the narrow CFAA "access" question, leaving contract questions open ([PYMNTS](https://www.pymnts.com/news/artificial-intelligence/2026/ninth-circuit-narrows-cfaa-reach-in-perplexity-agentic-commerce-ruling/)). That case shows Amazon goes to court over logged-in agents. Read as text, the AGENTEN section conditions agent access on self-identification rather than banning agents. The licence clause on collecting prices is a separate exclusion. Amazon's sanctioned routes (Product Advertising API, SP-API, any agent registration) were not researched.

## Conclusion

Bright Data's login block was never an industry standard. It is the legal position of one kind of vendor. Proxy networks like Bright Data, Oxylabs, Scrapeless and Zyte build their policies on the logged-out, public web, so they gate logins. Agent-browser vendors like Browserbase, Kernel, Anchor, Browser Use and Browserless sell logins as a feature and leave the target site's terms to the customer. Switching therefore does not remove the risk Bright Data was guarding against. It moves the risk from the vendor's KYC desk to T45's own policy. That makes the AGENTEN question — whether T45's agents present themselves as agents on sites that require it — a product decision T45 now owns, whichever vendor wins.

The comparison also shows something about T45's design. Reading pages needs only a URL and a substituted secret. Keeping logins needs a host-side owner for the session. Even the vendors that connect from a bare URL save state only through a stop call or a CDP command that Playwright CLI never sends. Plan on a small session broker on the runner, which creates sessions, attaches profiles, stops them and saves them, whichever vendor passes the bake-off. With that broker in place, a later change of vendor stays mostly inside the broker.
