# Remote browsers for AI agents: bot-block evidence and the EU legal/policy frame for logged-in agents

All URLs accessed or searched on 2026-11-12 (many legal sources were seen only in search summaries; see [snippet] tag). The amazon.de AGB and robots.txt were fetched directly with a browser-style User-Agent after the fetch tool got HTTP 503. Tags: **[vendor]** = published by a company selling a competing product; **[independent?]** = no commercial tie disclosed but independence not established; **[primary]** = the rule-maker's own text; **[snippet]** = seen only in a search-result summary, page not opened, so wording unverified. US rulings are labelled **(US law)**. Not legal advice; this reports what sources say.

## A1. Independent benchmarks of stealth/unblocking success, and which providers succeed on Amazon

### Takeaway

No independent, Amazon-specific benchmark of remote browsers (Browserbase, Steel, Hyperbrowser, Browserless, Anchor, Kernel, Browser Use, Airtop, Notte) was found; the stealth benchmarks that exist are vendor-run (Browser Use) or of undisclosed independence (Halluminate), use undisclosed site lists, and disagree on ranking. Amazon-specific success-rate data exists only for scraper APIs (Oxylabs, Decodo, ZenRows, Zyte, etc.), from an affiliate-funded review site with no published method.

### Cited Findings

- **[vendor] Browser Use "Stealth Bench" V1 (21 Mar 2026, author Aitor Mato, Browser Use Head of Browsers):** 71 sites where agents were getting blocked, drawn from ~300,000 security-check events (Cloudflare 23, PerimeterX 18, DataDome 13, Akamai 8, reCAPTCHA 6, Kasada/Shape 3); three steps per site (search, visit, read a link), no authentication; an LLM judge (gemini-2.5-flash) decides only "blocked or not"; page-load failures count as blocks; number of runs not stated; site list not published — [Browser Use blog](https://browser-use.com/posts/stealth-benchmark)
- V1 results: Browser Use Cloud 81%, Anchor 77%, Kernel 67%, Steel 47%, Browserbase 42%, Hyperbrowser 40%; controls on a GitHub Actions datacenter runner: headless Chromium 2%, headful Chromium 50% — [Browser Use blog](https://browser-use.com/posts/stealth-benchmark)
- V1 caveats stated by the author: proxy quality, site configs and CAPTCHA difficulty fluctuate; 71 sites is "a starting point"; no provider can guarantee 100% — [Browser Use blog](https://browser-use.com/posts/stealth-benchmark)
- **[vendor] Browser Use "Stealth Bench V2" (measured 25 Sep 2026):** 100 bot-protected sites × 2 runs; blind judge model checks whether the real site loaded within 60 s; each provider used its own proxy and CAPTCHA solver at the stealth level of its standard plan — [Browser Use, Cloud Browsers compared](https://browser-use.com/cloud-browsers)
- V2 results: Browser Use Cloud 90.5%, Anchor 82%, Kernel 80.5%, Browserbase 78.5%, Browserless 77.5%, Steel 74.5%, Hyperbrowser 73.5%; plain headless Chrome 3%, Chrome with a US proxy 14% — [Browser Use, Cloud Browsers compared](https://browser-use.com/cloud-browsers)
- V2 selection bias, admitted by the page: "The 100 sites were picked because Browser Use Cloud historically got through where stock Chrome with a US proxy did not"; the page calls the set "hard on purpose and not a balanced sample"; Browserbase, Hyperbrowser tested on standard modes and Steel with no stealth, not their top tiers — [Browser Use, Cloud Browsers compared](https://browser-use.com/cloud-browsers)
- A search summary claimed "an independent rerun put Steel at 74% and Browser Use Cloud at 90%" — **[snippet]**; contradicted by the fetched Browser Use page, which describes no independent rerun — [Browser Use, Cloud Browsers compared](https://browser-use.com/cloud-browsers)
- The benchmark code is open source; the repo states site tasks are encrypted to keep them out of crawlers/training data; Amazon is not mentioned; 27 forks, no third-party results found on the page — [GitHub browser-use/benchmark](https://github.com/browser-use/benchmark)
- **[independent?] Halluminate BrowserBench (22 Nov 2025 — older than 12 months):** 292 read-only tasks (5–25 steps) on 292 sites, ~150 "high-friction" sites and ~150 popular sites; Browser Use as agent framework and GPT-OSS as model, held constant; human reviewers as ground truth with an LLM judge calibrated to 90.4% agreement on stealth failures; no funding or ties to providers disclosed — [Halluminate](https://www.halluminate.ai/blog/browserbench)
- BrowserBench stealth failure rate (lower is better): Anchor stealth 1.7%, Hyperbrowser stealth 2.7%, Browserbase stealth 3.4%, Steel non-stealth 4.7%, Anchor non-stealth 5.0%, Hyperbrowser non-stealth 6.5%, Steel stealth 6.8%, Browserbase non-stealth 6.8% — [Halluminate](https://www.halluminate.ai/blog/browserbench)
- BrowserBench: stealth/CAPTCHA failures were 118 of agent failures (~15%) vs 668 (~85%) from other causes; authors call it "a directional signal", not "the final word"; Amazon not mentioned — [Halluminate](https://www.halluminate.ai/blog/browserbench)
- Conflict: Browser Use cites BrowserBench as "296 tasks" with per-provider task success (Browser Use Cloud 84.8%, Hyperbrowser 76.4%, Anchor 76.0%, Steel 73.3%, Browserbase 70.3%); Halluminate's own page shows 292 tasks and reports only stealth failure rates, and does not test Browser Use Cloud as a provider — [Browser Use blog](https://browser-use.com/posts/stealth-benchmark); contradicted by [Halluminate](https://www.halluminate.ai/blog/browserbench)
- **[vendor]** Anchor publishes a "benchmark results" page restating its BrowserBench lead (lowest stealth failure 1.7%) — **[snippet]** [Anchor Browser benchmark results](https://llms.anchorbrowser.io/anchor-browser-benchmark-results)
- **Amazon, scraper APIs (not remote browsers) — [independent?, affiliate-funded] Proxyway:** Decodo 99.5% / 3.88 s, ZenRows 98.51% / 3.97 s, Oxylabs 98.14% / 3.54 s, Zyte 97.78% / 2.58 s, Nimbleway 97.51% / 10.26 s, NetNut 97.4% / 6.14 s, ScrapingBee 97.05% / 4.29 s; no Bright Data or Scrapeless row; page dated 21 Oct 2026 but gives no request count, marketplace, success definition or test date; discloses affiliate links — [Proxyway, Best Amazon Scrapers](https://proxyway.com/best/best-amazon-scrapers)
- Search summaries say these Proxyway Amazon figures come from its **2025** Scraping API Report and are relabelled as 2026 on some pages — **[snippet]** [Proxyway best web scraping APIs](https://proxyway.com/best/best-web-scraping-apis)
- **[vendor]** Bright Data's blog is summarised as claiming "99.5% … highest … in the Proxyway 2025 benchmark for Amazon" (Proxyway attributes 99.5% to Decodo) and citing an AIMultiple 2026 test (1,400 URLs across 7 Amazon domains) at 99.98% for Bright Data — **[snippet]** [Bright Data blog](https://brightdata.com/blog/web-data/best-amazon-scrapers); [AIMultiple](https://aimultiple.com/amazon-scraper)
- One search summary states many providers count any HTTP 200 as success, including CAPTCHA pages and empty product pages, inflating headline rates — **[snippet]**, source not identifiable among [byteful](https://byteful.com/blog/best-amazon-scraper-api) / [webscraping.cc](https://webscraping.cc/blog/amazon-scraping-api/)

### Inferences

- Rankings flip by who runs the test: Browserbase is 3rd-best in Halluminate's stealth mode but 5th of 6 in Browser Use V1 and 4th of 7 in V2; Steel is better non-stealth than stealth in Halluminate. Treat any single ranking as weak evidence.
- Browser Use V2 reports 73.5–90.5% for every commercial provider vs 3–14% for stock Chrome, so "any managed stealth browser" is the big step; differences between vendors are within the noise of a vendor-chosen site set.
- Halluminate's split (85% of failures not stealth-related) suggests that for read tasks, agent/model errors matter more than blocking.
- For amazon.de price checks, the only Amazon-specific numbers concern scraper APIs that return parsed HTML/JSON, not interactive remote browsers; they are not evidence that any remote browser succeeds on Amazon.
- These benchmarks measure success at defeating bot detection — the behaviour the amazon.de Agenten-Bedingungen (B1 below) forbid for agents (no human mimicry, no CAPTCHA solving/bypass, mandatory "Agent/<name>" User-Agent).

### Gaps

- No independent, Amazon-specific (let alone amazon.de) test of any remote-browser provider found; no data on logged-in Amazon sessions.
- Airtop, Notte, Scrapeless, ZenRows browser, Oxylabs and Bright Data browser products appear in no stealth benchmark opened.
- No academic study or Hacker News/Reddit thread with reproducible numbers found within the search budget.
- Proxyway methodology and test dates not available on the page.

## A2. Reliability and speed: session start latency, page load, uptime

### Takeaway

The only systematic session-lifecycle data comes from Browser Arena, an open-source benchmark under the `nottelabs` GitHub org whose own product (Notte) ranks first; it measures create/connect/goto/release latency, not page-load speed under stealth. No uptime/status-page data was collected.

### Cited Findings

- **[vendor-run, open source] Browser Arena leaderboard, latest run 12 Nov 2026:** phases Create, Connect, Goto, Release; 100 runs per provider; sequential (c=1) and concurrent (c=10); repo under `nottelabs` — [Browser Arena](https://www.browserarena.ai/)
- Median latency / reliability / list cost per hour (12 Nov 2026): Notte 302 ms / 100% / $0.01; Tilion 104 ms / 100% / $0.03; Kernel 246 ms / 100% / $0.06; Lightpanda 440 ms / 100% / $0.06; Anchor 2,516 ms / 100% / $0.05; Cloudflare 898 ms / 100% / $0.09; Steel 1,228 ms / 100% / $0.10; TinyFish 590 ms / 100% / $0.12; Browserbase 795 ms / 100% / $0.12; AWS AgentCore 2,563 ms / 100% / $0.13; Browser Use 398 ms / 28% (72 of 100 failed, unranked); Hyperbrowser 0% (100 of 100 failed); Browserless and Airtop absent — [Browser Arena](https://www.browserarena.ai/)
- Earlier Browser Arena medians quoted by Browser Use (14 Oct 2026): Kernel 318 ms, Browser Use Cloud 493 ms, Browserbase 877 ms, Hyperbrowser 1,417 ms, Anchor 2,800 ms, Steel 3,509 ms; Browserless all runs failed with 401 — [Browser Use, Cloud Browsers compared](https://browser-use.com/cloud-browsers)
- ComputeSDK lifecycle scores (9 Oct 2026, as quoted by Browser Use): Tilion 98.4, Kernel 96.4, Browser Use Cloud 95.2, Hyperbrowser 94.0, Browserbase 92.8, Steel 77.2 — [Browser Use, Cloud Browsers compared](https://browser-use.com/cloud-browsers); source page [ComputeSDK](https://computesdk.com/benchmarks/browsers/lifecycle) not opened
- **[vendor]** List prices per browser-hour as compiled by Browser Use (checked Oct 2026): Browser Use Cloud $0.02; Anchor $0.05 + $0.01/browser; Kernel $0.06–0.48; Steel $0.08–0.10; Hyperbrowser $0.10; Browserbase $0.10–0.12; Browserless $0.18–0.24; residential proxy $5–12/GB — [Browser Use, Cloud Browsers compared](https://browser-use.com/cloud-browsers)
- Notte's own pages disagree on who leads latency (one says Notte, another says Kernel has "the fastest raw latency") — **[snippet]** [Notte arena](https://www.notte.cc/arena); [Notte answers](https://ai.notte.cc/answers/browserbase-vs-kernel)

### Inferences

- The 28% (Browser Use) and 0% (Hyperbrowser) rows are what was observed in one run on one day; they may reflect an API/auth change on the harness side (cf. Browserless "401" in October) rather than an outage. Do not read them as sustained reliability.
- Session start ranges ~0.1–3.5 s across providers; for a price-check agent that runs minutes per task, this is minor next to page-load and block rates.

### Gaps

- No provider status-page uptime history collected (Browserbase, Steel, Kernel, etc.).
- No page-load-time-under-stealth or residential-proxy latency comparison found.
- A search summary mentioned a 100-session test (Hyperbrowser 100, Browserbase 99, Steel 98) without an identifiable source; not included as a finding.

## B1. Amazon's terms on robots/data mining and agents (amazon.de)

### Takeaway

Amazon.de's own AGB (last changed 01.10.2026) both (a) exclude from the user licence any collection and use of prices and any use of robots/data-mining tools, and (b) contain a dedicated "AGENTEN" section that permits agents only if they self-identify with an `Agent/<name>` User-Agent and do not mimic human behaviour, solve or bypass CAPTCHAs, or circumvent agent-blocking measures. A stealth remote browser reading amazon.de prices, logged in or not, is contrary to these terms on their face.

- **[primary] LIZENZ UND ZUGANG:** licence is "beschränkte, einfache, nicht übertragbare und nicht unterlizenzierbare Lizenz für den Zugriff und die nicht-kommerzielle Nutzung der Amazon Services. ### Inferences

- The AGB separately exclude (i) "Erfassung und Nutzung von … Preisen" and (ii) robots/data mining from the licence; competitor price monitoring by a business is squarely what the text excludes, whether done by a human-driven tool or an agent.
- The Agenten section does not ban agents outright: it conditions access on self-identification and no anti-detection. An agent acting inside the user's own Amazon account that sends `Agent/<name>` and does not use stealth would at least meet the agent-specific conditions (it would still face the licence's price-collection exclusion and Amazon's right to block). A stealth remote browser fails the conditions by design.
- Whether these AGB bind a logged-out visitor (no clickwrap) is a German contract-law question; BGH case law (B2) treats AGB breach alone as insufficient for UWG unfairness but treats circumvention of technical protection as potentially unfair — the Agenten terms explicitly label CAPTCHA solving and human mimicry as circumvention.
- The Perplexity ruling is US federal criminal-statute (CFAA) law and does not apply in the EU; its value is as a signal that Amazon litigates against agentic access, specifically logged-in agents.

### Gaps

- Effective date/history of the Agenten section (whether introduced on 01.10.2026 or earlier) not established.
- Amazon's sanctioned routes (Product Advertising API / SP-API, "Agent/<name>" registration process) and their terms not researched.
- No EU court decision applying Amazon's AGB to scrapers or agents found.

## B2. EU and German case law and guidance on scraping and automated access (Database Directive, UWG, criminal law, GDPR, AI Act)

### Takeaway

EU law lets a site restrict use of an unprotected database by contract (Ryanair v PR Aviation, 2015) and protects databases with substantial investment against extraction that harms that investment (CV-Online, 2021); German courts held that scraping public pages despite AGB is not in itself unfair competition, but overcoming technical protection can be (BGH Flugvermittlung, 2014; World of Warcraft II, 2017). GDPR applies only where pages contain personal data; for the AI Act, only Art. 5 was opened and no general scraping rule was found beyond the ban on untargeted facial-image scraping.

### Cited Findings

- **CJEU C-30/14 Ryanair v PR Aviation (15 Jan 2015):** the Database Directive does not apply to a database protected neither by copyright nor by the sui generis right, so it does not preclude the database's author from imposing contractual limitations on third-party use, subject to national law; facts: PR Aviation screen-scraped Ryanair flight data — **[snippet]** [IPPT judgment copy](https://www.ippt.eu/sites/ippt/files/2015/IPPT20150115_ECJ_Ryanair_v_PR_Aviation.pdf); [Kluwer Copyright Blog](https://legalblogs.wolterskluwer.com/copyright-blog/ryanair-ltd-v-pr-aviation-bv-contracts-rights-and-users-in-a-low-cost-database-law/); [Portolano](https://portolano.it/news/ecj-clarifies-database-directive-scope-in-screen-scraping-case)
- Commentary notes the contract route only binds parties who accepted the terms (privity) and depends on national law — **[snippet]** [Kluwer Copyright Blog](https://legalblogs.wolterskluwer.com/copyright-blog/ryanair-ltd-v-pr-aviation-bv-contracts-rights-and-users-in-a-low-cost-database-law/)
- **CJEU C-762/19 CV-Online Latvia v Melons (3 Jun 2021):** a specialised search engine copying/indexing a freely accessible database extracts and re-utilises it; this infringes the sui generis right where it adversely affects the maker's investment (building on Innoweb C-202/12) — **[snippet]** [SCL headline](https://www.scl.org/12290-cjeu-search-engine-copying-of-databases-infringes-sui-generis-right-where-it-adversely-affects-database-maker-investment/); [Bird & Bird](https://www.twobirds.com/en/insights/2021/uk/cv-online-latvia-cjeu-complicates-the-enforcement-of-database-rights); [Kluwer Copyright Blog](https://copyrightblog.kluweriplaw.com/2021/06/17/access-to-information-and-competition-concerns-enter-the-sui-generis-rights-infringement-test-the-cjeu-redefines-the-database-right/?output=pdf); judgment copy [IPPT](https://www.ippt.eu/sites/ippt/files/2021/IPPT20210603_CJEU_CV-Online_Latvia_v_Melons.pdf)
- **BGH I ZR 224/12 "Flugvermittlung im Internet" (30 Apr 2014):** no unfair obstruction (§ 4 Nr. 10 UWG old) by a portal screen-scraping Ryanair; "allein das Ignorieren der per Mausklick akzeptierten Allgemeinen Geschäftsbedingungen (AGB)" is not enough; "Das Überwinden technischer Schutzvorrichtungen könnte zwar unlauter sein"; remanded to OLG Hamburg — [LTO](https://www.lto.de/recht/hintergruende/h/bgh-urteil-izr22412-screen-scraping-flugdaten-automatisiert-auslesen-ryanair-reiseportal)
- BGH 2014 reasoning per commentary: a site operator must accept losing ad revenue when users do not visit its site (citing Paperboy, Automobil-Onlinebörse) — **[snippet]** [husovec.eu](https://husovec.eu/2014/04/bgh-screen-scraping-does-not-constitute-html/); [Ferner Alsdorf](https://www.ferner-alsdorf.de/screen-scraping-wettbewerbsrechtlich-nicht-zwingend-ein-problem/)
- **BGH I ZR 253/14 "World of Warcraft II" (12 Jan 2017):** protection of a business model built on AGB against targeted obstruction (§ 4 Nr. 4 UWG) applies only where those rules are legally binding; mere disregard of contract terms is generally not anti-competitive; circumventing a protective measure against interference with a competitor's product is generally unfair; sale of WoW bots enjoined — **[snippet]** [Betriebs-Berater](https://betriebs-berater.ruw.de/wirtschaftsrecht/nachrichten/Missachtung-von-Geschaeftsbedingungen--World-of-Warcraft-II--31951); [Gleiss Lutz](https://www.gleisslutz.com/de/gleiss-lutz-erstreitet-f%c3%bcr-blizzard-entertainment-grundsatzurteil-vor-dem-bgh-vertrieb-von-bot.html); [rewis.io](https://rewis.io/urteile/urteil/i0r-12-01-2017-i-zr-25314/)
- **§ 202a StGB (Ausspähen von Daten):** requires overcoming an access safeguard designed to exclude or substantially hinder third-party access (BGH NStZ 2011, 154); a password can suffice; using a colleague's credentials without permission is the textbook case — **[snippet]** [§ 202a StGB text](https://www.gesetze-im-internet.de/stgb/__202a.html); [Jurafuchs](https://wissen.jurafuchs.de/definitionen/jqnv40k/gegen-unberechtigten-zugang-besonders-gesichert-%C2%A7-202a-abs-1-stgb); [Ferner Alsdorf](https://www.ferner-alsdorf.de/sicherung-des-zugangs-mittels-passwort-reicht-als-zugangssicherung-im-sinne-des-%c2%a7202a-stgb/)
- **TDM / § 44b UrhG — OLG Hamburg 5 U 104/24 (Kneschke v LAION, 10 Dec 2025):** upheld LG Hamburg 310 O 227/23 (27 Sep 2024); a natural-language reservation of use did not meet § 44b(3) machine-readability; Revision to the BGH admitted, so not final — **[snippet]** [heise](https://heise.de/-11111575); [beck-aktuell](https://www.beck-aktuell.de/heute-im-recht/rechtsprechung/olg-hh-5u10424-nutzung-foto-ki-training-2025-12-10); [Justiz Hamburg press release](https://justiz.hamburg.de/resource/blob/1126574/2495057737fed4883eec42dce4d2430b/ki-und-urheberrecht-hanseatisches-oberlandesgericht-weist-berufung-zurueck-data.pdf)
- **GDPR — CJEU C-621/22 KNLTB (4 Oct 2024):** a purely commercial interest can be a legitimate interest under Art. 6(1)(f) if lawful; necessity and balancing still apply — **[snippet]** [Hunton](https://huntonak.com/privacy-and-information-security-law/cjeu-rules-on-scope-of-legitimate-interest-basis-under-the-gdpr); [BAILII judgment copy](https://www.bailii.org/eu/cases/EUECJ/2024/C62122.html)
- **GDPR — Dutch AP scraping guidance (1 May 2024):** headline position "scraping is almost always illegal"; treated purely commercial interests as not legitimate interests, pending C-621/22 (since decided against that reading) — **[snippet]** [IAPP](https://iapp.org/news/a/netherlands-dpa-issues-guidance-against-web-scraping); [Taylor Wessing](https://www.taylorwessing.com/de/interface/2024/democracy-in-the-digital-age/elections-and-web-scraping); [Pinsent Masons](https://www.pinsentmasons.com/out-law/news/dutch-web-scraping-guidance-warn-businesses-gdpr-breach-risk)

### Inferences

- Amazon's AGB expressly invoke "Datenbankrecht" and "wesentliche Teile"; under CV-Online, occasional reading of a handful of competitor product prices is far from the systematic substantial extraction the sui generis right targets, but a bulk price database built from Amazon would sit closer to it.
- German UWG case law makes the decisive factor technical-protection circumvention, not AGB breach; stealth fingerprinting and CAPTCHA solving are exactly what Amazon's Agenten terms now describe as measures to distinguish computers from humans, which strengthens a "circumvention" argument against stealth agents.
- § 202a StGB turns on overcoming access protection "unbefugt"; an agent logging in with the account holder's own credentials at the holder's request does not fit the textbook pattern (using someone's credentials without permission), but no source found addresses consented agent logins.
- Price data on product pages is mostly non-personal; GDPR becomes relevant on supplier portals or seller pages that show named individuals (sole traders, contact persons), where Art. 6(1)(f) after KNLTB is the likely basis, with minimisation.
- No AI Act provision found that regulates agents reading web pages; the facial-image ban is irrelevant to price checks.

## B3. Credential handling: is it sensible for an agent to log in with a user's credentials, and what vendor terms say

### Takeaway

The four vendors checked — Browser Use (page opened), Kernel, Anchor and Browserbase (docs seen as snippets) — actively support logged-in agents (credential vaults, 1Password, TOTP, persistent profiles); login support for the other nine (incl. scraping networks Oxylabs, ZenRows, Scrapeless, likeliest to share Bright Data's restriction) is unverified. None of the opened terms (Browserbase, Anchor) forbids logging into third-party sites; Steel's terms are the strictest, forbidding use "to violate any website's terms of service, robots.txt, or similar access restrictions" and making the customer obtain permissions. The binding constraint is therefore the target site's own terms (e.g. Amazon's Agenten section) and sector law (PSD2/PSR for bank accounts), not the browser vendor.

### Cited Findings

- **[vendor] Browser Use Cloud:** profile sync of a real Chrome profile, 1Password service-account integration where "the agent retrieves and fills credentials automatically", automatic TOTP via `bu_2fa_code` placeholders; page says nothing about target-site ToS or consent (updated 25 Oct 2026) — [Browser Use, web agent authentication](https://browser-use.com/posts/web-agent-authentication)
- Same page notes Steel blurs filled credential fields so vision-based agents cannot read them — [Browser Use, web agent authentication](https://browser-use.com/posts/web-agent-authentication)
- **[vendor] Kernel Managed Auth:** stores credentials once and re-authenticates automatically; credentials from 1Password or saved from a login; `totp_secret` for fully automated 2FA; hosted login page; credentials API does not return secret values — **[snippet]** [Kernel auth overview](https://kernel.sh/docs/auth/overview); [Kernel credentials](https://kernel.sh/docs/auth/credentials)
- **[vendor] Anchor:** browser profiles persist cookies/local storage but "do not store credentials"; Managed Authentication "runs the auth flow automatically before each session"; customers "never required to store credentials on our platform"; 1Password runtime retrieval — **[snippet]** [Anchor managed authentication](https://docs.anchorbrowser.io/essentials/managed-authentication); [Anchor + 1Password](https://anchorbrowser.io/hub/securing-agentic-browsers-anchor-joins-the-launch-of-1password-unified-access)
- **[vendor] Browserbase:** 1Password integration injects credentials and TOTP at runtime without storing or logging secrets — **[snippet]** [Browserbase 1Password](https://www.browserbase.com/1password)
- **Browserbase Terms of Use (last updated 1 Aug 2025, California law):** prohibits unlawful use and "any robot, spider, or other automatic device … to access the Platform" (i.e. Browserbase itself); no clause found on circumventing third-party bot detection, violating third-party ToS, credential stuffing, account takeover or logging into third-party accounts — [Browserbase ToS](https://www.browserbase.com/terms-of-service)
- **Anchor Application Terms (last updated 25 May 2025, New York law, ICC arbitration; dated URL, not confirmed as the current version):** bans circumventing "security-related or technical features or protocols of the Service" (Anchor itself); customer must comply with laws "including … privacy laws"; no clause found on third-party ToS, scraping, credential stuffing or third-party logins — [Anchor terms](https://anchorbrowser.io/saas-terms-05-25-2025)
- **Steel Terms of Service (last updated 5 Feb 2025, Delaware law), §8:** "Use the Services to bypass security measures, access controls, or authentication systems without authorization"; "Use the Services to violate any website's terms of service, robots.txt, or similar access restrictions"; "Use the Services to circumvent paywalls…"; "Use the Services to collect personal data without proper consent or legal basis"; "Engage in activities that violate the Computer Fraud and Abuse Act (CFAA) or similar laws in other jurisdictions" — [Steel terms](https://steel.dev/terms)
- Steel §27: user "solely responsible" for legal compliance and must "obtain all necessary permissions and authorizations before accessing any websites, systems"; indemnity for third-party-rights violations — [Steel terms](https://steel.dev/terms)
- Steel §11: "you represent and warrant that you are entitled to disclose your Third-Party Account login information to us … without breach by you of any of the terms and conditions that govern your use of the applicable Third-Party Account" (context suggests linking third-party accounts to Steel; scope for agent logins unclear) — [Steel terms](https://steel.dev/terms)
- **Bright Data AUP:** forbidden activities include "Collection of nonpublic information (i.e data behind login)", "Creating fake accounts", "Impersonation or spoofing for fraudulent purposes" — [Bright Data AUP](https://docs.brightdata.com/general/policy/acceptable-use-policy)
- **PSD2 (RTS on SCA & CSC, Delegated Reg. (EU) 2018/389):** final standards ended screen scraping by third-party providers once dedicated interfaces apply, with a fallback mechanism (Art. 33) that ASPSPs can be exempted from — **[snippet]** [Pinsent Masons](https://www.pinsentmasons.com/out-law/news/psd2-screen-scraping-ban-confirmed-in-finalised-standards); [paytechlaw](https://paytechlaw.com/en/screen-scraping/)
- **PSD3/PSR:** provisional political agreement 27 Nov 2025; commentary says access via the customer interface (screen scraping) is prohibited and the fallback interface dropped; application projected for 2027 — **[snippet]** [Taylor Wessing](https://www.taylorwessing.com/en/insights-and-events/insights/2025/11/eu-lawmakers-strike-a-deal-on-payments-reforms); [Linklaters](https://techinsights.linklaters.com/post/102lw95/psd3-breakthrough-eu-legislators-agree-payments-regulation-reforms); [binar](https://binar-com-website.pages.dev/insights/psd3-psr-end-of-psd2-era)
- **(US law)** Ninth Circuit in Amazon v. Perplexity treated the user, not the agent developer, as the party accessing the site under the CFAA, "on the record before the court" and fact-specific — [PYMNTS](https://www.pymnts.com/news/artificial-intelligence/2026/ninth-circuit-narrows-cfaa-reach-in-perplexity-agentic-commerce-ruling/)
- **Amazon.de AGB** require the user to keep their password confidential and govern any agent the user "verwenden, zulassen, aktivieren" — [amazon.de AGB](https://www.amazon.de/gp/help/customer/display.html?nodeId=201909000)

### Inferences

- Moving from Bright Data to Browserbase/Anchor/Kernel/Browser Use removes the vendor-side login block; with Steel, logging into a site whose ToS forbid automated access would breach Steel's own terms as well.
- Vendor silence (Browserbase, Anchor) is not permission: their general "comply with applicable law" clauses and indemnities shift third-party ToS risk to the customer (T45), who in turn would shift it to its users.
- Sharing passwords with a third-party platform typically conflicts with the target site's account terms (Amazon: keep password confidential); vault-based injection (1Password) limits exposure but does not change the contractual position.
- For bank accounts, PSD2/PSR channel third-party access through dedicated interfaces for licensed providers; an agent driving a business's online-banking UI is the pattern regulators have moved to prohibit for TPPs, and banks' own terms typically forbid credential sharing — a reason to exclude banking sites.

### Gaps

- Terms/AUPs of Hyperbrowser, Kernel, Browser Use, Browserless, Airtop, Notte, Scrapeless, ZenRows and Oxylabs not opened; login support for Hyperbrowser, Browserless, Airtop, Notte, Steel (beyond credential blurring), Scrapeless, ZenRows and Oxylabs not verified.
- Bank-side terms (e.g. German/Italian banks' online-banking conditions on credential sharing) not researched.
- Whether PSR is formally adopted/published in the Official Journal as of Nov 2026 not confirmed.
- No EU source found on liability allocation when an agent acts in a user's account (EU analogue of the Perplexity question).

## B4. Why Bright Data restricts logins, versus vendors that allow them

### Takeaway

Bright Data's whole legal position is built on "public web data = accessible without logging in": its AUP forbids collecting data behind a login, its Browser API disables password entry by default "so that no data behind a login is collected," and exceptions need KYC (registered businesses only) plus compliance approval; it frames the logged-out line as its strongest legal defence, which US litigation (Meta v. Bright Data) rewarded.

### Cited Findings

- **[primary] Bright Data Browser API KYC page:** "Password entry is disabled so that no data behind a login is collected", tied to the AUP; password entry requires "KYC, then compliance approval"; request it during KYC or via compliance@brightdata.com after KYC — [Bright Data KYC and access](https://docs.brightdata.com/products/scraping-browser/kyc-and-access)
- Same page: "KYC applications are accepted only from registered businesses", company email domain needed, every submission human-reviewed, not available in Playground/Limited Trial; robots.txt-disallowed URLs, government sites and blocked classifications need KYC; `brul` targets need compliance approval; restrictions apply "no matter what the target's robots.txt allows" — [Bright Data KYC and access](https://docs.brightdata.com/products/scraping-browser/kyc-and-access)
- Browser API may switch from residential to datacenter proxies for some KYC-gated domains "for compliance" — **[snippet]** [Bright Data KYC and access](https://docs.brightdata.com/products/scraping-browser/kyc-and-access)
- Residential-proxy KYC applies to residential zones created after 7 Jul 2026 — **[snippet, Chinese-language docs]** [Bright Data residential network access](https://docs.brightdata.com/cn/proxy-networks/residential/network-access)
- **[primary] Bright Data ethics guide:** "Public web data means content accessible without logging in." "If data requires a login, sits behind a paywall, or needs restricted access credentials, it is not public data." "Public access reduces legal risk significantly compared to scraping behind logins." "Being able to demonstrate this distinction (through code, policies, or audits) is one of the strongest defenses you can have." — [Bright Data ethical web scraping](https://docs.brightdata.com/scraping-automation/concepts/ethical-web-scraping)
- **[primary] Bright Data AUP:** "Collection of nonpublic information (i.e data behind login)" listed as forbidden — [Bright Data AUP](https://docs.brightdata.com/general/policy/acceptable-use-policy)
- **(US law) Meta v. Bright Data (N.D. Cal., Jan 2024):** Judge Chen granted Bright Data summary judgment on breach of contract; Meta's terms reached logged-in use, not logged-off scraping of public data; Meta later dropped the suit — **[snippet]** [TechCrunch](https://techcrunch.com/2024/01/24/court-rules-in-favor-of-a-web-scraper-bright-data-which-meta-had-used-and-then-sued); [Farella Braun + Martel](https://www.fbm.com/technology/publications/major-decision-affects-law-of-scraping-and-online-data-collection-meta-platforms-v-bright-data/); [MediaPost](https://www.mediapost.com/publications/article/393996/meta-abandons-lawsuit-against-bright-data-over-scr.html)
- (US law) X Corp. v. Bright Data: one summary says the complaint was dismissed months later (Techopedia, as cited by Bright Data material); another found no ruling — conflicting **[snippet]** [Bright Data blog](https://brightdata.com/blog/data-ethics/assessing-the-legality-of-web-scraping)
- Bright Data's Jennifer Burns told publishers to put content behind a login, i.e. login as the line between public and non-public — **[snippet]** [The Next Web](https://thenextweb.com/news/jennifer-burns-bright-data-public-web-data-login-tnw-podcast)
- 2023: Scraping Browser halted with "Forbidden action: password typing is not allowed" (historical, predates KYC flow) — **[snippet]** [Stack Overflow mirror](https://kaweah.freedombox.rocks/kiwix/stackoverflow.com_en_all_2023-11/questions/76131573/bright-data-scraping-browser-forbidden-action-password-typing-is-not-allowed)
- Contrast: Steel forbids violating site ToS but has no product-level password block; Browserbase and Anchor terms have neither a ToS-compliance clause nor a login block; Browserbase, Anchor, Kernel and Browser Use ship credential features — [Steel terms](https://steel.dev/terms); [Browserbase ToS](https://www.browserbase.com/terms-of-service); [Anchor terms](https://anchorbrowser.io/saas-terms-05-25-2025); [Browser Use, web agent authentication](https://browser-use.com/posts/web-agent-authentication)

### Inferences

- Bright Data's login block protects Bright Data (a proxy network operator whose litigation wins depended on staying logged-out), not T45's users; vendors without the block simply leave the logged-in risk with the customer.
- The logged-out/logged-in line matters legally because logging in normally means accepting the site's terms (clickwrap), which is what made contract claims fail against Bright Data in Meta and what Ryanair v PR Aviation lets EU site operators rely on.
