# Simplification findings

Reviewed commit `1ed7125` in several passes: models and resources, server implementations, frontend callers, then the constraints behind the promising cuts. This was a source review; no implementation changes or tests were run. Proposed replacements have not been verified.

The strongest pattern is representing the same information twice, then maintaining code to reconnect it. Estimated reductions below are production LOC (inferred), excluding tests, and are not measured patches.

## Investigated and worth keeping

- Automation failure-as-result handling: throwing immediately inside the transaction would roll back the recorded `lastError`. The `Result` conversion has a concrete purpose. [AutomationService.ts](../../apps/server/src/automations/AutomationService.ts#L83)
- Workflow permission loaders: people can comment on closed tickets; automated callers require an open ticket and working step. Combining these paths would conceal a real distinction. [WorkflowService.ts](../../apps/server/src/workflows/WorkflowService.ts#L294)
- Chat delta reconciliation and history-page joining: they preserve streamed text beyond the persisted message copy and avoid joining history across a missing window. Deleting them sacrifices existing behavior. [state/chats.ts](../../apps/web/src/state/chats.ts#L88), [history joining](../../apps/web/src/state/chats.ts#L241)

## Suggested order

Next: simplify authentication storage. Then remove the pasted-text flag, simplify image persistence, remove automatic upload retry, and remove refresh-and-wait. These cuts are approved, including their listed tradeoffs. Keep the attachment prompt envelope.
